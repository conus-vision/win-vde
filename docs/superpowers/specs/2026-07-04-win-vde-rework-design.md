# win-vde — Rework Design (Virtual Desktop Extension for Windows 11)

> Дизайн доработки существующей трей-утилиты `vde.cpp`: автоматическое
> восстановление раскладки окон по виртуальным десктопам, защита сохранённой
> раскладки от затирания, поддержка Chrome/Edge и generic-программ, а также
> улучшения пикера. Публичный OSS-репозиторий: `conus-vision/win-vde`, MIT.

Дата: 2026-07-04 · Статус: утверждается · База: `vde.cpp` (единый Win32/C++ файл)

---

## 1. Контекст и цель

Утилита — резидент в трее для Windows 11. Умеет:
- Хоткей (Ctrl+Alt+D) → пикер-сетка десктопов: клик = переключиться, Ctrl+клик = перенести активное окно на десктоп.
- Save/Restore раскладки Firefox: читает `sessionstore` (recovery.jsonlz4), строит домен-фингерпринт окна, сопоставляет окна между перезапусками (HWND эфемерный) и **переносит окно на его виртуальный десктоп**.
- Auto-fix: таймер ~10 c пере-сохраняет `layout.txt` при изменении раскладки.
- Перемещение чужих окон — через недокументированные COM-интерфейсы ImmersiveShell (IID захардкожены под сборки 24H2/25H2, совместимо с 22631). Чтение десктопа окна — документированный `GetWindowDesktopId`.

**Важно:** файл `firefox-desktop-manager-design.md` в исходной папке описывает *гипотетическую* C#/.NET+WebExtension+SQLite архитектуру и **не отражает** реальный код. Источник истины — `vde.cpp`.

Цель доработки — сделать восстановление раскладки **автоматическим и устойчивым**, распространить на Chrome/Edge и другие многооконные программы, и улучшить пикер.

## 2. Ключевые решения (согласовано)

| Вопрос | Решение |
|---|---|
| Что есть «положение окна» | **Только виртуальный десктоп** (desktop-only). Геометрию (X/Y/размер) не сохраняем — её восстанавливает сам браузер. |
| Другие приложения | **Chrome/Edge парсим отдельно** (SNSS-сессии) + generic-программы по заголовку/exe. Firefox — как есть. |
| Автовозврат | Только при **старте утилиты** (если окна уже открыты) и при **появлении окон после полного отсутствия**. Не трогаем окна во время обычной работы. |
| Автозапуск | **Переключатель** в настройках (HKCU\...\Run). |
| Лицензия | **MIT**. |
| Объём | **Фазы 1+2+3** целиком; реализация пофазно с коммитами. |

## 3. Требования (из запроса)

R1. При старте утилиты: если открыто ≥1 окно Firefox — авто-restore. Если Firefox не запущен — мониторить запуск; как только запущен, подождать ~20 c (стабилизация) и восстановить раскладку.
R2. При выходе утилиты — сохранять положение окон, **только если открыто ≥1 окно**.
R3. Периодическая проверка сохранения: если окон приложения **вообще нет** — не менять записи; когда окна появились — восстановить. Никогда не затирать всю раскладку из-за того, что пользователь закрыл окна.
R4. Распространить поведение на другие браузеры / многооконные программы.
R5. Пункты меню:
   - `Save windows layout` — сохраняет **отдельный** файл с текущим положением.
   - `Restore saved windows layout` — восстанавливает из этого файла.
   - `Restore last auto saved layout` — восстанавливает последнюю **авто**-точку.
R6. Авто-раскладка: временное закрытие окна не должно стирать его из раскладки; повторное открытие — восстанавливать. Удалять запись окна только после **2-3 перезапусков утилиты**.
R7. Строка поиска в пикере: сверху, placeholder «Type window name to search», фильтрует окна в плитках по вводу.
R8. Скролл в плитках, если окна не помещаются.
R9. Тултип полного имени окна при наведении, если имя обрезано по горизонтали (как alt у картинок).
R10. Подсказку Ctrl+Click визуально выделить.

Мета: создать `win-vde/`, git, залить на GitHub, написать README.

## 4. Модель данных

Каталог данных: `%LOCALAPPDATA%\VirtualDesktopsExtention\` (как сейчас).

Два файла раскладки вместо одного `layout.txt`:

| Файл | Пишет | Семантика |
|---|---|---|
| `layout-auto.txt` | монитор | «последняя авто-точка», обновляется **слиянием** (merge) |
| `layout-manual.txt` | меню *Save windows layout* | ручной чекпоинт, **полная перезапись** текущего состояния |

> Миграция: при старте, если существует старый `layout.txt` и нет `layout-auto.txt` — переименовать его в `layout-auto.txt`.

### 4.1 Формат записи

Формат — расширение текущего TSV (`# VDE snapshot v3`). Строки:

```
# VDE snapshot v3
D<TAB>index<TAB>{guid}<TAB>b64(name)                                                              # десктоп
W<TAB>app<TAB>deskIndex<TAB>{guid}<TAB>b64(activeTitle)<TAB>activeDomain<TAB>tabCount<TAB>counts<TAB>missingRuns   # окно
```

Отличия от v2: в строке `W` добавлены поле `app` (какое приложение) и `missingRuns` (grace-счётчик). Чтение v2 поддерживается (app="firefox", missingRuns=0).

`counts` — как сейчас: `domain:n,domain:n,...` (мультимножество eTLD+1 доменов вкладок окна). Для generic-программ без доменов `counts` пуст, сопоставление идёт по `activeTitle`+app.

### 4.2 Grace-период (R3, R6) — защита от затирания

Проблема сейчас: `RunSave` перезаписывает файл только текущими окнами → окно, временно закрытое пользователем, теряется из раскладки.

Решение — **merge-запись** авто-файла + счётчик `missingRuns`, стареющий по запускам утилиты:

- **Авто-save (периодический, в течение сеанса)**: обновляет записи присутствующих сейчас окон (десктоп, `missingRuns=0`). Записи отсутствующих окон **сохраняются без изменений** (не удаляются, счётчик не трогается). Если окон приложения сейчас нет вовсе — файл не трогаем.
- **«Seen-set» сеанса**: монитор копит множество отпечатков окон, замеченных хотя бы раз за текущий запуск утилиты.
- **Reconcile (при выходе утилиты, R2)**: если за сеанс наблюдали ≥1 окно приложения:
  - запись в seen-set → `missingRuns = 0`;
  - запись не в seen-set → `missingRuns += 1`; если `missingRuns ≥ 3` — удалить.
  - Если за сеанс окон приложения не наблюдали вовсе — записи этого приложения не трогаем.

Порог `MISSING_RUNS_MAX = 3` покрывает «2-3 перезапуска». Стойкие записи безопасны: они срабатывают только если окно с тем же отпечатком снова появится.

## 5. Жизненный цикл (конечный автомат монитора)

Монитор ведёт по каждому отслеживаемому приложению состояние `present`/`absent`. Тик таймера `MONITOR_INTERVAL_MS` (по умолчанию 5000).

```
              ┌─ старт утилиты ─┐
              │                 │
        окна есть?          окон нет
              │                 │
   settle ~2-3 c            ожидание
   AUTO-RESTORE                 │
              │        absent → present (запуск/session-restore)
              ▼                 ▼
          PRESENT  ◄──── settle ~20 c → AUTO-RESTORE
        периодич. AUTO-SAVE (merge, дебаунс по изменению раскладки)
        копим seen-set
              │
     present → absent  →  НИЧЕГО НЕ СТИРАЕМ
              │
        выход утилиты  →  если present: финальный AUTO-SAVE; затем reconcile grace
```

Правила:
- **Старт, окна уже открыты (R1)** → короткая стабилизация (~2-3 c), затем авто-restore из `layout-auto`.
- **Старт, приложение не запущено (R1)** → ждём. Переход `absent→present` → стабилизация **~20 c** (окно count не меняется), затем авто-restore.
- **present** → авто-save по изменению раскладки (дебаунс), интервально.
- **present→absent** → не стираем (R3).
- **Выход (R2)** → если ≥1 окно есть, финальный save; reconcile grace-счётчиков.

Параметры: `STARTUP_SETTLE_MS=2500`, `LAUNCH_SETTLE_MS=20000`, `MONITOR_INTERVAL_MS=5000`, `RESTORE_STABLE_TICKS` (кол-во тиков без изменения count для «стабильно»).

Авто-restore подчиняется режиму (согласовано «Старт и появление окон») — непрерывного возврата в течение сеанса нет.

Защита от повторов: после успешного авто-restore для данного «появления» ставим флаг, снимаем его при переходе `present→absent`. Так одно появление окон = один restore.

## 6. Коллекторы (мульти-приложение, R4)

Абстракция: **Collector** для приложения даёт список отпечатков окон (для сопоставления между перезапусками) и умеет привязать отпечаток к живому HWND (для переноса на десктоп).

```
struct AppProfile {
  std::wstring id;             // "firefox" | "chrome" | "msedge" | generic-id
  std::vector<std::wstring> exeNames;   // firefox.exe / chrome.exe / msedge.exe
  std::vector<std::wstring> classNames; // MozillaWindowClass / Chrome_WidgetWin_1
  std::vector<std::wstring> titleSuffixes; // " - Mozilla Firefox", " - Google Chrome", " - Microsoft Edge"
  SessionSource session;       // FIREFOX_SESSIONSTORE | CHROMIUM_SNSS | NONE
};
```

Живые окна: обобщаем `EnumFirefoxWindows` до `EnumAppWindows(profile)` — фильтр по classNames + exeNames. Привязка отпечатка к HWND — по совпадению `activeTitle` (заголовок окна без суффикса) с активной вкладкой из сессии (как сейчас у Firefox).

| Коллектор | class / exe | Источник отпечатка |
|---|---|---|
| Firefox | MozillaWindowClass / firefox.exe | sessionstore (есть) |
| Chrome | Chrome_WidgetWin_1 / chrome.exe | **SNSS** (нов.) |
| Edge | Chrome_WidgetWin_1 / msedge.exe | **SNSS** (нов., тот же движок) |
| Generic | любой exe (из настроек) | заголовок + exe + класс (без доменов) |

### 6.1 Chromium SNSS (Chrome/Edge)

Профиль: `%LOCALAPPDATA%\Google\Chrome\User Data\<Profile>\` (Edge: `...\Microsoft\Edge\User Data\<Profile>\`). Профиль «Default» + доп. из `Local State` (список профилей). Файлы сессии: `Sessions\Session_<ts>` (последний по времени) либо `Current Session`.

Формат SNSS: magic `SNSS` + version(int32), затем поток команд `int16 length` + `length` байт (первый байт — command id, далее base::Pickle-пейлоад с 4-байтным выравниванием). Для восстановления текущего состояния «проигрываем» лог: интересуют команды навигации вкладки (URL/title), привязки вкладки к окну, закрытия вкладок/окон, выбор активной вкладки. Итог — по окну: мультимножество доменов + заголовок активной вкладки.

**Устойчивость (обязательно):** command id менялись между версиями Chromium. SNSS-коллектор оборачивается в try/best-effort: при любой ошибке разбора — **фолбэк на generic** (заголовок+exe). Домены нужны лишь для более точного сопоставления; без них деградируем до заголовка, а не падаем. Заголовок окна Chrome/Edge = «<active tab> - Google Chrome»/«… - Microsoft Edge» → те же суффиксы отрезаем.

### 6.2 Настройки приложений

В настройках — чекбоксы включения по приложению (Firefox / Chrome / Edge) и опциональный список generic-exe. Отслеживаются только включённые.

## 7. Save / Restore — семантика

- `RunSave(target)` обобщается: `AUTO` (merge в `layout-auto.txt`, grace) и `MANUAL` (полная перезапись `layout-manual.txt`, без grace).
- `RunRestore(file)` — из указанного файла. Ядро сопоставления (`Score`, назначение по порогам `T_FLOOR=0.35`, `T_ACCEPT=0.55`) остаётся; добавляется фильтр по `app` (окно сопоставляется только с записями своего приложения).
- Меню (R5): `Save windows layout` → MANUAL save; `Restore saved windows layout` → restore из manual; `Restore last auto saved layout` → restore из auto.
- Тексты балунов обновляются («N windows across M desktops»). Ярлык «Firefox» в меню убирается (теперь мульти-app).

## 8. Пикер (Switch popup) — UX

### 8.1 Строка поиска (R7)
Child-контрол `EDIT` сверху окна пикера. Placeholder «Type window name to search» (через `EM_SETCUEBANNER`). Фокус на поле при показе пикера. По `EN_CHANGE` — фильтр: в плитках остаются только окна, чей заголовок содержит введённую подстроку (регистронезависимо). Плитки без совпадений — притушены. Клавиши: Esc — закрыть; стрелки/цифры/Enter управляют сеткой (нужно аккуратно развести фокус между полем и сеткой — субклассинг EDIT, форвардинг «навигационных» клавиш в основное окно). Layout сетки сдвигается вниз на высоту поля.

### 8.2 Скролл в плитках (R8)
Убираем «+N more». У каждой плитки — свой `scrollOffset` (в элементах). Отрисовка списка окон клипуется прямоугольником плитки. `WM_MOUSEWHEEL`: hit-test плитки под курсором → меняем её offset → перерисовка. Тонкий индикатор скролла (▲/▼ или полоска), когда есть переполнение.

### 8.3 Тултип полного имени (R9)
Стандартный tooltip-контрол (`TOOLTIPS_CLASS`). При `WM_MOUSEMOVE` определяем окно под курсором и, **только если его имя было отрисовано с эллипсисом** (полная ширина текста > ширины строки), показываем tooltip с полным заголовком. `TrackMouseEvent` для ухода курсора.

### 8.4 Подсветка Ctrl+Click (R10)
Подсказка «Ctrl+Click = move window» рисуется как акцентный **бейдж**: скруглённый прямоугольник с акцентным фоном (например, синий `RGB(0,120,215)` фон, белый текст) вместо тусклой серой строки. Когда зажат Ctrl — бейдж ярче/подсвечен (уже есть перерисовка по WM_KEYDOWN/UP VK_CONTROL). Рядом — обычная «Click = switch».

```
┌───────────────────────────────────────────────────────┐
│  [ Type window name to search…                     ]   │
│  Switch to: Desktop 2            Click=switch [Ctrl+Click=move] │
│  ┌── Desktop 1 ─────┐   ┌── Desktop 2 ─────┐  ▲        │
│  │ ▤ GitHub — PR#42 │   │ ▤ Jira board     │  │        │
│  │ ▤ Docs — Python  │   │ ▤ Mail — Inbox   │  ▼        │
│  └──────────────────┘   └──────────────────┘           │
└───────────────────────────────────────────────────────┘
```

## 9. Настройки и автозапуск

Окно Settings дополняется:
- **Start with Windows (run at logon)** — чекбокс. On → `RegSetValueExW(HKCU\Software\Microsoft\Windows\CurrentVersion\Run, "VirtualDesktopsExtention", exePath)`; off → удалить значение. Путь берём из `GetModuleFileNameW`.
- Переименовать авто-режим: «Auto-save & auto-restore layout».
- Чекбоксы приложений: Firefox / Chrome / Edge.

Все значения — в `HKCU\Software\VirtualDesktopsExtention` (как `AutoFix`, `HotkeyMods`, `HotkeyVk`).

## 11. Фазы реализации

1. **Ядро (Firefox):** два файла + grace/merge + `missingRuns`; автомат жизненного цикла (старт-restore, ожидание запуска +20 c, save-on-exit, no-wipe); relabel меню (R5); автозапуск-переключатель; миграция `layout.txt`. + инициализация repo (src/, build.bat, .gitignore, LICENSE, README).
2. **Мульти-app:** `AppProfile`/коллекторы; Chromium SNSS-ридер (Chrome+Edge) + фолбэк на generic; фильтр по `app` в сопоставлении; чекбоксы приложений.
3. **Пикер UX:** строка поиска, скролл в плитках, тултип полного имени, бейдж Ctrl+Click.

Каждая фаза — отдельные коммиты; собираемость проверяется после каждой.

## 12. Edge cases и риски

- **SNSS-хрупкость** — главный риск. Митигируется try/best-effort + generic-фолбэк + изоляция в Фазу 2.
- **Неизвестная сборка Windows** (COM-IID не совпали) — как сейчас: сервисы не инициализируются, GUI показывает ошибку / degraded. Авто-restore при этом не выполняется.
- **DPI/geometry** — не актуально: geometry не восстанавливаем.
- **Приватные окна** Firefox — sessionstore их не содержит → сопоставляются только по заголовку (как сейчас).
- **Несколько профилей** браузера — берём активный/дефолтный; несовпадение не критично (деградация до заголовка).
- **Гонка при старте** — restore только после стабилизации count (не по голому таймеру), с verify-after-move (уже есть: `VerifyOnDesktop`, до 4 попыток).
- **Elevated-браузер** — неуправляем неэлевейтед-треем (UIPI); детектируем неявно (перенос вернёт ошибку), не крешимся.
- **Пустые окна** (`about:blank`, пустой домен-сет) — помечаются как non-restorable (нет отпечатка).

## 13. Тестирование

Логика без GUI покрывается юнит-тестами в отдельном exe (в духе `vdtest_test.cpp`):
- mozLz4 decode, JSON-парсер, `hostOf`/`etld1` (есть/расширить).
- **SNSS-ридер**: разбор фикстур `Session_*` (Chrome/Edge) → ожидаемые окна/домены; повреждённый файл → пустой результат (не креш).
- **Merge/grace**: сценарии — окно исчезло на N сеансов; появилось снова; все окна закрылись (нет затирания); `missingRuns` растёт/сбрасывается/удаляет при ≥3.
- **Сопоставление**: фильтр по `app`; пороги `T_FLOOR`/`T_ACCEPT`.
- Строковые: сериализация/десериализация v3, обратная совместимость чтения v2.

GUI (пикер, тултип, скролл, автозапуск, жизненный цикл) — ручная проверка на реальной машине (COM виртуальных десктопов и трей не гоняются в CI).

## 14. Вне объёма (YAGNI)

- Восстановление геометрии окон.
- WebExtension + native messaging (из гипотетического дизайн-дока).
- SQLite/история снапшотов — остаёмся на плоских файлах.
- Разнесение вкладок одного окна по десктопам.
